# Как редактировать новости

Источник сайта — `updates.json` в корне репозитория. Одинаковые данные используются на главной и на странице `updates/`.

Самый простой способ обновить сайт: открыть `updates.json` в GitHub → карандаш Edit → внести изменения → Commit changes. После успешной публикации GitHub Pages обновить страницу. Файл в папке «Документы» не синхронизируется автоматически.

## Формат
- `updates`: проверенные и уже выпущенные изменения. Поля `id`, `title`, `type` обязательны; `description`, `date` (YYYY-MM-DD), `area`, `version` можно добавить. Тип: `new`, `improved`, `fixed`.
- `knownIssues`: подтверждённые проблемы. Статусы: `known`, `in_progress`, `fix_pending_verification`, `fixed`.
- `roadmap`: планы. `in_progress` — в работе, `planned` — далее.

Каждая запись должна иметь уникальный стабильный `id` внутри своего списка. Текст отображается как обычный текст, не HTML. Даты не генерируются автоматически.

Записи в `updates` по умолчанию считаются вручную утверждёнными к публикации. Добавляйте туда только выпущенные и проверенные изменения. Для черновика укажите `"published": false` или `"verified": false` — запись будет скрыта. `fixed` у проблемы убирает её из активного списка, но не создаёт новость автоматически.

Пример новой записи (поместить внутрь updates, запятые между записями):
```json
{
  "id": "short-stable-id",
  "title": "Краткое название",
  "description": "Что стало удобнее для преподавателя.",
  "area": "Hub",
  "type": "improved",
  "published": false
}
```
После фактической публикации и проверки укажите реальную дату и уберите `published: false`.

Не оставляйте запятую после последнего элемента. JSON не поддерживает комментарии. При ошибке формата сайт покажет сообщение о недоступности обновлений; каталог игр продолжит работать.
